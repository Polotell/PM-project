## 4. 分支约定
- `main`：受控发布分支，仅保留课程提交与检查所需的最终定稿成果。  
- `dev`：日常集成分支，成员成果先汇总到该分支并完成冲突处理。  
- `feature-<成员拼音>`：成员个人工作分支，从最新 `dev` 拉取并独立提交。  
- 协作流程：`feature-* -> dev -> main`。  
- 责任分工：配置管理员负责 `feature-* -> dev` 合并；项目经理负责 `dev -> main` 最终合并。

## 6. 提交说明
- 关键成果统一使用 Markdown 文档，便于版本比较、协作评审与冲突处理。  
- 文档命名与课程模板保持一致，不随意重命名，正文统一使用 UTF-8。  
- 提交信息建议采用：`<类型>: <简短中文说明>`。  
- 示例：`docs: 完成配置管理方案`、`docs: 补充 WBS 三级条目`、`fix: 解决 conflict.md 合并冲突`。  
- 每位成员应保留可追溯独立提交记录，不伪造、不回撤公共历史掩盖协作过程。  
- 禁止未经沟通强制推送改写公共分支历史；冲突处理后需清理标记并重新提交。  
- `docs/conflict.md` 作为冲突演练记录文件保留在仓库中，用于复盘与验收佐证。
