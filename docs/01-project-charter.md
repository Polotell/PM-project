# 01 项目启动说明

## 1. 项目名称
校园活动报名与签到管理系统

## 2. 项目目标
- 支持活动发布
- 支持学生报名
- 支持签到与统计

## 3. 团队分工
- 王昊宇：配置管理员
- 朱紫阳：计划负责人
- 杨吝时：项目经理

## 4. 项目边界


- 纳入范围

| 序号 | 范围项 | 说明 |
|:---:|---|---|
| 1 | **活动信息发布与维护** | 活动管理人员可发布活动信息，维护报名时间、人数上限、活动地点等基本信息 |
| 2 | **学生报名信息提交** | 学生可查看活动列表并在线提交报名申请 |
| 3 | **报名名单查看与审核** | 活动组织者能够查看报名名单，并对报名申请进行审核操作 |
| 4 | **签到记录与签到状态管理** | 支持现场二维码签到，记录签到状态（已签到/未签到） |
| 5 | **签到统计结果导出** | 活动结束后可导出基本的签到统计结果 |
| 6 | **项目管理工作成果** | 项目仓库与目录结构、WBS 文档、简化进度计划文档、配置管理文档、总结报告 |

- 不纳入范围

| 序号 | 范围项 | 说明 |
|:---:|---|---|
| 1 | **复杂支付功能** | 不涉及报名费收取、退款、财务结算等支付相关功能 |
| 2 | **与真实校园统一身份认证系统的深度对接** | 不接入学校实际的统一身份认证（如 CAS、LDAP 等），采用简化身份验证方式 |
| 3 | **高并发优化与正式部署方案** | 不做大规模并发性能优化，不提供生产环境正式部署架构 |
| 4 | **移动端 App 正式开发** | 不开发原生 iOS/Android App，如有移动端需求仅考虑 Web 适配或简化方案 |
| 5 | **高保真产品级开发** | 本实验以项目管理成果为核心，不要求完成完整的产品级软件开发 |

- 边界说明

本项目为**软件项目管理实验**，核心交付物是**项目管理文档与过程成果**，而非商业级软件产品。
系统功能实现以**轻量级、流程清晰、记录完整**为原则，满足基本业务场景即可。
技术实现上采用简化方案，重点体现项目管理过程中的 WBS 分解、进度计划、配置管理和团队协作。

## 5. 主要交付物
- 项目仓库
- WBS 文档
- 进度计划文档
- 配置管理文档
- 总结报告
